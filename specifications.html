Présentation du projet

VoyageVista est une application web de voyage haut de gamme permettant aux utilisateurs de découvrir des destinations, de composer des itinéraires personnalisés (transports, hébergements, activités) et de finaliser leurs réservations en ligne. La plateforme adopte un positionnement premium avec une charte graphique dorée sur fond sombre et des animations soignées.

L'application repose sur une architecture 3 tiers stricte : un front-end SPA React 19 communiquant exclusivement via REST avec un back-end PHP 8 sans framework, lui-même relié à une base de données MySQL. L'authentification est gérée par des tokens JWT signés en HMAC-SHA256.

Rôles utilisateurs

L'application distingue trois profils d'utilisateurs authentifiés, auxquels s'ajoute le visiteur anonyme. Chaque rôle est stocké dans la colonne role de la table users et vérifié côté serveur via la fonction requireRole() du middleware JWT.

🧳 Voyageur

Traveler

Utilisateur final qui cherche à planifier et réserver des voyages. Rôle attribué par défaut à l'inscription.

  • Parcourir le catalogue de destinations
  • Créer et modifier des itinéraires
  • Réserver et payer en ligne
  • Consulter l'historique de réservations
  • Gérer ses favoris
  • Déposer des avis sur les destinations
  • Recevoir des notifications
🏨 Prestataire

Provider

Fournisseur de services (hôtels, transporteurs, agences d'activités). Compte créé manuellement ou validé par un administrateur.

  • Publier des offres (hébergements, transports, activités)
  • Gérer les disponibilités et les prix
  • Consulter les réservations liées à ses offres
  • Confirmer ou annuler des réservations
  • Accéder à un tableau de bord prestataire
🛡️ Administrateur

Admin

Super-utilisateur avec accès complet à toutes les données. Rôle attribué manuellement en base de données.

  • Accès au tableau de bord global
  • Gérer tous les utilisateurs (rôles, suppression)
  • Créer, modifier, supprimer des destinations
  • Modérer les avis et le contenu
  • Consulter l'ensemble des réservations
  • Envoyer des notifications ciblées
ℹ️
Visiteur anonyme : accès en lecture seule au catalogue de destinations. Toute action (itinéraire, réservation, avis, favoris) déclenche une redirection vers la page de connexion. La section « Créer un compte gratuit » de la page d'accueil est masquée lorsqu'un utilisateur est déjà connecté.

Contraintes techniques

Sécurité

🔑

Authentification JWT obligatoire sur toutes les routes protégées

Chaque appel API sensible vérifie la présence et la validité du token JWT via requireAuth(). Un token expiré ou altéré retourne immédiatement un 401 Unauthorized. Le secret de signature ne doit jamais être exposé côté client.

💉

Protection contre les injections SQL

Toutes les interactions avec la base de données passent par des requêtes PDO préparées avec paramètres liés. Aucune concaténation directe de données utilisateur dans les requêtes SQL n'est tolérée.

🛡️

Contrôle d'accès par rôle (RBAC)

Les routes d'administration et de prestataire utilisent requireRole(['admin']) ou requireRole(['provider','admin']). La vérification se fait côté serveur — la restriction front-end n'est qu'un complément visuel.

Performance

⚡

Optimisation du bundle frontend

Vite 8 / Rolldown produit un bundle optimisé avec tree-shaking. Framer Motion et Lucide React sont importés sélectivement (import nommé) pour éviter le chargement de l'intégralité de la bibliothèque.

📦

Pagination des listes

Les endpoints GET /api/destinations, GET /api/bookings et GET /api/notifications supportent les paramètres page et limit pour éviter le chargement de milliers d'enregistrements en une seule requête.

Compatibilité

🌐

Navigateurs modernes ciblés

L'application cible les navigateurs récents (Chrome 120+, Firefox 121+, Edge 120+, Safari 17+). Aucun polyfill IE11 n'est prévu. Le HashRouter de React Router garantit la compatibilité avec les serveurs sans configuration de réécriture d'URL.

📱

Design responsive

L'interface est conçue en mobile-first avec des breakpoints CSS à 768 px et 1024 px. La navigation mobile utilise un menu hamburger. Les grilles de cartes passent de 3 colonnes (desktop) à 1 colonne (mobile).

Données & Intégrité

🔗

Intégrité référentielle MySQL

Les clés étrangères sont déclarées avec ON DELETE CASCADE ou ON DELETE SET NULL selon le cas. La suppression d'un utilisateur entraîne la cascade sur ses itinéraires, réservations, favoris et notifications.

📋

Validation des données

Validation côté client (formulaires React) et côté serveur (PHP) pour tous les champs critiques : email format, mot de passe longueur minimale 8 caractères, dates cohérentes (départ < retour), prix positifs.

Environnement de développement

🔧

Configuration isolée du code source

Toutes les variables sensibles (secrets JWT, identifiants base de données, URLs d'API) sont stockées dans des fichiers .env.local non versionnés. Le dépôt Git contient un fichier .env.example comme référence.

🚫

Paiement simulé — pas de passerelle réelle

La fonctionnalité de paiement est simulée à des fins pédagogiques. Aucun SDK bancaire réel (Stripe, PayPal) n'est intégré. Le formulaire collecte des données fictives et crée uniquement une entrée en base avec le statut confirmed.
